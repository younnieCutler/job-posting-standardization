# 벤치마킹 — 선행 서비스 분석과 JDF 화면 설계 반영

작성 2026-09-02 · 대상 화면: `app/dashboard.py` (표준화 검증 리포트)

## 왜 벤치마킹하나

JDF 리포트의 독자는 **일본 IT 채용 계획을 세우는 HR/TA 데이터 분석 담당자**다.
같은 종류의 문제(여러 출처의 채용공고를 표준화해 비교 가능하게 만들기)를 실제로 푸는
서비스가 이미 있다. 각 서비스가 "어떤 질문에 답하게 하는가"를 보고, JDF 화면이 답해야 할
질문과 답하지 말아야 할 질문을 정한다.

## 한눈에 — 4개 레퍼런스의 역할 분담

| 참고 서비스 | 우리가 참고한 점 | JDF 적용 |
|---|---|---|
| **Lightcast** | 직무·스킬 공통 언어 (Taxonomy 관점) | 표기 통일 · 직무 분류 |
| **HRog** | 일본 채용시장 분석 방식 (시장/화면 관점) | 직무 · 경력 · 채널 분석 |
| **Revelio Labs** | 의사결정 중심 시장 리포트 (종합 리포트 관점) | HR/TA용 종합 리포트 구조 |
| **TheirStack** | 공고 구조화 · 기술 추출 (공고 데이터 제품화 관점) | 스킬 키워드 통합 |

가장 가까운 레퍼런스: **HRog**(일본 시장·화면), **Lightcast**(표준화·Taxonomy),
**Revelio**(종합 리포트), **TheirStack**(공고 데이터 제품화).

---

## Lightcast

- **주요 고객**: 기업 HR·인재개발, 대학·교육기관, 정부·노동시장 연구기관
- **고객이 해결하려는 문제**: 출처마다 직무명·스킬명 표기가 달라(예: "백엔드 개발자" vs
  "Backend Engineer") 데이터를 비교·합산할 수 없다
- **어떤 데이터를 보여주나**: 표준화된 직무명(Open Titles), 직업 분류(Occupation),
  스킬 사전(Open Skills)과 이들로 정규화된 채용공고·이력서·정부 통계
- **대표 분석 축**: 직무 · 스킬 · 직업 분류 · 지역 · 시간
- **어떤 질문에 답하나**: "이 스킬의 수요가 지역별로 어떻게 다른가", "이 직무명은 어떤
  표준 직업으로 묶이나"
- **JDF가 참고할 부분**: `표기 통일 → 직무 분류 → 스킬 분류` 3단 설계. 같은 의미의 여러
  직무명·스킬 표기를 하나의 공통 언어로 모으는 방향
- **JDF가 현재 구현하지 못한 부분**: 직무 분류(Taxonomy) 매핑 자체가 없음. 스킬은
  정규식 키워드 매칭 + 표기 변형 병합 수준이며, Lightcast 같은 완성된 스킬 분류 체계가
  아니다 — **화면에서 이걸 "완성된 스킬 Taxonomy"로 표현하지 않는다**

**JDF 화면 반영**: "원본 직무명이 어떻게 같은 직무 분야로 묶이는가", "같은 스킬의 여러
표기가 어떻게 하나로 집계되는가"를 보여주는 방향. 현재는 후자의 축소판(키워드 통합)만 구현.

## HRog (株式会社フロッグ)

일본 채용시장과 가장 직접적으로 가까운 벤치마크.

- **주요 고객**: 인재소개회사·헤드헌팅·구인미디어 운영사, 기업 인사팀, 관공서·대학·언론
- **고객이 해결하려는 문제**: 경쟁사가 지금 어떤 직무를 얼마나 채용 중인지, 시장 전체
  채용 흐름이 어떤지를 여러 사이트를 일일이 돌지 않고 보고 싶다
- **어떤 데이터를 보여주나**: 다수 일본 채용매체를 통합·정제한 데이터. 지금 채용 중인
  기업 리스트(HRog リスト), 직종·지역·매체 기준 시장 분석(HRog チャート), 지역별
  시급·채용현황 지도(HRog マップ), 기업명·공고 정제 서비스(HRog クレンジング)
- **대표 분석 축**: 지역 · 직종 · 매체 · 시간 · 고용형태
- **어떤 질문에 답하나**: "어느 직종의 공고가 늘고 있나", "어느 지역·매체에 공고가
  몰리나", "경쟁사는 어떤 포지션을 채용 중인가"
- **JDF가 참고할 부분**: 복잡한 내부 데이터 구조를 노출하지 않고, 사용자가 바로
  이해하는 **시장 질문 중심** 화면. 지역/직종/매체 축의 단순 집계
- **JDF가 현재 구현하지 못한 부분**: 시계열(추세), 지역 축(합성 데이터에 근무지 있으나
  분석 축으로 미사용), 실제 시장 규모 — **JDF의 합성 데이터를 실제 일본 시장 수요로
  표현하지 않는다**

> **수치 주의**: HRog 제품별로 공식 수치가 다르다. HRog チャート는 약 150개 매체,
> HRog リスト는 2026년 기준 250개 이상 매체·60억 건 이상으로 표시된다. 제품 범위가
> 다른 숫자이므로 "HRog = 정확히 N억 건"으로 강조하지 않고 **"다수 일본 채용매체를
> 통합·정제해 시장 분석에 제공"** 으로만 쓴다.

**JDF 화면 반영**: "어떤 직무의 공고가 많은가", "어떤 경력 수준에서 채용 수요가 많은가",
"어떤 채널에서 공고가 많이 관측되는가", "표준화 전후 데이터가 어떻게 달라졌는가".

## Revelio Labs

- **주요 고객**: 기관투자자·헤지펀드, 기업 전략·인사기획, 컨설팅
- **고객이 해결하려는 문제**: 기업·산업의 인력 동향(누가 뽑히고, 얼마 받고, 어디로
  이동하는지)을 표준화된 형태로 비교하고 싶다
- **어떤 데이터를 보여주나**: 채용공고(Job Posting), 급여(Salary), 직무(Role), 지역
  (Geography), 경력 수준(Seniority), 채용·이탈(Hiring/Attrition)을 하나의 표준 체계로
  정규화한 Workforce Intelligence(인력시장 분석) 플랫폼
- **대표 분석 축**: 기업 · 직무 · 지역 · 경력 수준 · 급여 · 스킬 · 시간
- **어떤 질문에 답하나**: "이 회사의 채용이 늘고 있나 줄고 있나", "이 직무의 시장 급여
  분포는", "인력이 어느 산업으로 이동하나"
- **JDF가 참고할 부분**: 단순 데이터 조회가 아니라 **의사결정 질문 중심**의 리포트 구성.
  각 화면 위에 "이 화면을 보는 사람"과 "이 화면으로 답하려는 질문"을 명시하는 방식
- **JDF가 현재 구현하지 못한 부분**: 채용률·이탈률·지원자 경쟁률·실제 시장 급여
  벤치마크 — **JDF에 없는 이 지표들을 만들지 않는다**. 시계열, 기업 단위 비교도 없음

**JDF 화면 반영**: 모든 섹션 상단에 `이 화면을 보는 사람` + `이 화면으로 답하려는 질문`
한 줄. 예: "채용 계획 담당자 — 어떤 직무에서 채용 수요가 많이 발생하는가?"

## TheirStack

- **주요 고객**: 세일즈·마케팅팀(타깃 기업 발굴), 리크루터, 시장 분석가
- **고객이 해결하려는 문제**: 채용공고 원문은 형식이 제각각이라, 기술 스택·직무·지역·급여
  같은 조건으로 검색·분석하기 어렵다
- **어떤 데이터를 보여주나**: 여러 소스에서 수집한 채용공고를 정규화해 구조화 필드
  (기술 스택, 직무, 지역, 급여 등)로 제공. API로 판매
- **대표 분석 축**: 기술 스택 · 직무 · 지역 · 급여 · 회사
- **어떤 질문에 답하나**: "이 기술을 쓰는 회사가 어디인가", "이 조건의 공고를 뽑아줘"
- **JDF가 참고할 부분**: 여러 형태로 적힌 기술 키워드를 통합해 보여주는 화면. 공고
  소스와 정규화 결과를 함께 확인할 수 있는 구조
- **JDF가 현재 구현하지 못한 부분**: 공고 본문에서의 스킬 추출이 정규식 키워드 매칭
  수준 — **AI 기반 완성형 스킬 추출로 과장하지 않는다**. 급여·지역의 구조화 필드도 없음

**JDF 화면 반영**: "여러 형태로 적힌 기술 키워드를 통합해서 보여주는 화면", "채용공고
소스와 정규화 결과를 확인할 수 있는 화면".

## 벤치마킹 → 화면 설계 요약

| 벤치마킹 결과 | 화면 반영 |
|---|---|
| Revelio: 의사결정 질문 중심 | 모든 섹션에 "보는 사람 / 답하려는 질문" 한 줄 |
| HRog: 시장 질문 중심, 내부 구조 비노출 | 차트 제목을 질문형으로, 개발자용 컬럼명 화면에서 제거 |
| Lightcast: 표기 통일 → 분류 | "원본 직무명 → 정리된 직무명", "스킬 표기 통합" 을 Standardization Quality에서 보여줌 |
| TheirStack: 공고 소스 + 정규화 결과 확인 | Channel/Source 섹션 + Real ATS 부록에서 소스별 분포 |
| 공통: JDF에 없는 지표 금지 | 채용률·이탈률·경쟁률·실제 시장 급여 벤치마크 미구현 → 만들지 않음, Methodology에 명시 |
