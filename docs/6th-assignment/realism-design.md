# 합성 일본어 채용공고 리얼리티 설계 — 4층 스택

작성 2026-09-01 · 상태: 1·3·4층 이번 라운드 / 2층 다음

## 왜 이 문서

"가짜 데이터가 너무 티나게 가짜"라는 문제. 진짜에 가깝게 만들려면 리얼리티를
한 덩어리로 보지 말고 **층으로 나눠** 각각 다른 소스로 채워야 한다.
건수(10만+)는 나중 문제 — 뼈대부터.

프로젝트 제약: 실제 스크래핑 금지(ADR-005), 파이프라인 런타임에 LLM 금지
(메모리 결정 `project_jdf-synthetic-dataset-design`). 리얼리티는 "더 많은 실데이터"가
아니라 "더 나은 합성"으로 확보한다.

---

## 층별 정의

### 1층 · 분포 리얼리티 — 厚労省 job tag (O-NET 일본판) 【이번】

- **소스**: https://shigoto.mhlw.go.jp/User/download
  - 500+ 직업의 職業解説 + 数値情報
  - 태스크(직업에 포함된 세부 업무), 필요 학력·자격·실무경험, 労働時間, **賃金**,
    就労者数, 就労者 평균연령, しごと能力プロフィール(スキル·知識·흥미·가치관)
- **라이선스**: "職業解説" 및 "職業の数値情報"은 편집·가공·재집계 등 2차 이용 허용.
  (심리검사 3종 문항만 복제 금지 — 우리가 쓸 영역 아님)
- **적용**:
  | 현재 (손으로 적음/추측) | → job tag 실측치 |
  |---|---|
  | `JOB_FAMILY_GROUPS` (6그룹, 손 목록) | 실제 직종명 + 태스크 목록 |
  | `SALARY_BANDS_MAN_YEN` (junior/mid/expert 추측 밴드) | 직종별 실제 賃金 분포 |
  | `TIER_THRESHOLD_PHRASES` (경력요건 문구) | 직종별 실제 필요 실무경험 |
  | `SKILL_POOL_BY_GROUP` (그룹별 스킬 손 매핑) | 직종별 しごと能力 스킬·知識 프로파일 |
- **내일 첫 작업**: 다운로드 페이지에서 실제 파일 포맷(xlsx/csv/구조) 확인 → 파싱 →
  `synth_rules.py` 풀 교체 → `verify_coverage.py` 통과 확인

### 2층 · 언어 리얼리티 — JOBSKAPE 오프라인 문장뱅크 【다음 단계】

- **참조**:
  - JOBSKAPE — arxiv 2402.03242, github `magantoine/JobSkape`
    (이 프로젝트 스펙 "Data source strategy"에서 이미 인용)
  - JobSet — ACM 2024, `10.1145/3672608.3707718` (오프라인 리얼리티 메트릭)
- **JOBSKAPE 실제 방법**: ① 택소노미에서 "같이 등장할 법한" 스킬 조합 생성
  ② LLM으로 조합별 다양한 현실 문장 렌더 ③ 정제
- **우리 적용 (런타임 LLM 금지 우회)**:
  - LLM을 **오프라인 1회**만 실행 → (직군 × 스킬조합 × 섹션)별 현실 문장 템플릿
    수천 개 생성 → `data/templates/sentence_bank.jsonl`로 커밋 (정적 자산)
  - 런타임 생성기는 뱅크에서 골라 슬롯필만 → 결정적, LLM 미호출
  - 스킬조합 입력: 1층 job tag 스킬 프로파일 재사용 (ESCO 등 외부 택소노미 불필요)
- **작업량**: 1일+ → 마감 밖. 시간 남으면 소규모 1차 뱅크만

### 3층 · 구조 리얼리티 — 템플릿 풀 확장 【이번】

- 현재: 섹션 문장이 사실상 1종 (`{title}としてご活躍いただきます。`)
- 목표: 섹션별(`職務内容` / `必須要件` / `歓迎要件` / `待遇`) 골격 **30~50개** 손작성,
  중첩 슬롯 (`{task}` / `{skill_phrase}` / `{tier_phrase}` / `{location}` 등)
- 플랫폼별 필드명·급여 포맷 차이는 이미 `PLATFORM_PROFILES`에 있음 → 확장만
- 새 파일: `ingestion/synth_templates.py`
- 결정적·빠름·무비용. 한 줄씩 보면 그럴듯, 100개 연속이면 반복 티 — 대시보드·매칭
  데모엔 충분

### 4층 · 지저분함 리얼리티 — 골든셋 56행 【기존, 유지】

- `SKILL_VARIANTS` — `Python` / `パイソン` / `PYTHON`, `機械学習` / `ML` 등 표기 흔들림
- `FIELD_NAME_VARIANTS` — `職務内容` / `仕事内容`
- `TIER_BLEND` (15%), `COVERAGE_GAP` (30%)
- 이게 정규화 대상 그 자체 → **안 건드림**

## 볼륨 계획

- `N_ROLES` 상수 (현재 160). 이번 목표 5,000~15,000건 → `N_ROLES` ~2,000~5,000
  (롤당 2~5 변형)
- `SEED=42` 유지 → 재현 가능
- 플랫폼별 parquet write → 전체를 한 DataFrame에 안 들고 있음, 메모리 문제 없음
- 느리면: 청크 write, 또는 문자열 생성만 Mimesis(Faker 빠른 사촌)로 교체
- 10만+ 스케일업은 뼈대 검증 후 별도
